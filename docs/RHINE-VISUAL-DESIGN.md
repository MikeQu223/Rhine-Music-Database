# Rhine Music DataBase 视觉与界面设计规范

本文供设计、实现和审阅页面的智能体及开发者使用。它把「档案终端」状态栏与歌曲详情、发现音乐、专辑详情设计稿归纳为同一套视觉语言，目标是在新增页面时保持一致的气质、信息层级和交互体验。

这是一份**设计目标和示意稿规范**，不表示所有页面已经按此实现。文中颜色与结构是设计基准，示意数据、英文档案文字和尺寸不是业务接口或固定内容。采用此规范时必须先核对实际功能和数据，保留已有动作、页面关系及平台输入能力。

移动端现有布局、坐标、动画、页面交互和验收边界见 [响应式 HUD 维护指南](RHINE-MOBILE-DESIGN.md)。该指南描述现有实现；本文件不改变其中的功能和平台约束。实现与示意稿不一致时，先保留现有功能，再明确需要调整的设计，不凭示意稿删除功能或重建业务逻辑。

## 1. 设计定位

把音乐播放器想象为**莱茵生命内部使用的音频资料库**：歌曲是一份可播放的档案，专辑是实体资料与曲目目录，发现音乐是可浏览的研究资料索引。

视觉气质是：**冷静、严谨、轻工业、科研机构、纸质档案、克制的未来感**。重点是准确组织信息和操作，让用户快速理解当前内容；装饰为信息提供秩序感，而不是把页面变成复杂的科幻仪表盘。

## 2. 一眼可辨的风格

一张符合本规范的页面应同时具有以下特征：

1. **纸色底与深色字**：背景为偏灰绿的暖白，主要文字接近深墨绿黑，避免纯白背景与纯黑大面积堆叠。
2. **清楚的档案层次**：英文小标题或编号作为辅助标识，中文功能名与实际内容清楚、优先可读。标题、字段、操作和说明各占明确层级。
3. **细线与留白组织内容**：使用对齐、间距、1 逻辑像素分割线和少量色块。主要信息区域可以有一条更深的顶部结构线。
4. **琥珀色只强调关键状态**：用在选中下划线、当前曲目侧条、进度、少量节点或重要提示。正常内容不因为装饰被染黄。
5. **直角、平面和细节**：矩形面板及按钮以直角为主，轮廓清晰；少量圆环、唱片、轨道、十字准星可以作为与音乐或科研相关的细节。
6. **封面是内容主体**：保留真实封面比例和辨识度，载体、边框与编号应衬托封面。已有三维唱片、场景和交互的页面要尊重它们的角色，不应因为二维示意替换或遮挡主体。

避免：通用后台仪表盘式的大圆角卡片、饱和霓虹、玻璃拟态、夸张投影、全页面网格、无意义的数据读数、不断闪烁的线条，以及为了「科技感」堆放难以阅读的英文。不要把每个信息块都画成有边框的盒子。

## 3. 颜色与语义

以下颜色来自面板设计稿；状态栏稿使用过非常接近的暖白与深绿，可统一使用此表，避免各页面出现不同版本的纸色。十六进制为 sRGB，不带透明度。用语义名称引用，避免散落硬编码。

| 语义 token | 值 | 用途 |
| --- | --- | --- |
| `surface.canvas` | `#F1F0E7` | 页面底色、资料库背景 |
| `surface.panel` | `#F8F7EE` | 档案信息面板、弹层和可读内容区 |
| `surface.secondary` | `#E5E7DA` | 次级色块、标签底、精选区 |
| `surface.player` | `#E4E6D8` | 播放栏主体 |
| `surface.playerFoot` | `#D9DECC` | 播放栏最底部状态带 |
| `ink.primary` | `#222A25` | 正文、标题、深色按钮及结构线 |
| `ink.secondary` | `#626B60` | 辅助说明、字段名、时间和次级文字 |
| `line.default` | `#CCCEC0` | 分隔线、次按钮轮廓、列表行边界 |
| `accent.visual` | `#D5A348` | 选中线、进度填充、节点和少量装饰 |
| `accent.text` | `#805600` | 浅色表面上的琥珀色可读文字 |
| `status.errorText` | `#994320` | 浅色表面上的错误文字，配合图标及文案 |

`accent.visual` 和 `#C18A28` 等较亮金黄适合线条和色块，不适合在浅底上作为小正文。参考对比度：`ink.primary` / `surface.panel` 约 **13.70:1**，`ink.secondary` / `surface.panel` 约 **5.15:1**，`accent.text` / `surface.panel` 约 **6.01:1**。实际呈现须考虑透明度、背景图片和平台渲染：正文及可操作文字至少达到 4.5:1，大号文字及必要控件图形至少达到 3:1；状态不可只靠颜色区分。

深色「轨道信号」是曾做过的**备选方向**，不是所有页面默认跟随系统切换的要求。若明确需要深色场景，可使用 `#222923` 深绿黑背景、`#EDF0DF` 主文字、`#A5AD9D` 次文字与琥珀点缀；逐项重新验证对比度，不要仅对浅色界面反色。

## 4. 字体、标点与文案

### 字体角色

| 角色 | 基准 | 用法 |
| --- | --- | --- |
| 页面标题 | 28–36 逻辑像素，约 600–700 字重 | 歌名、专辑名、发现音乐；短标题可更大 |
| 分区标题 | 16–20 逻辑像素，约 500–600 字重 | 推荐歌单、曲目目录、档案区块 |
| 常规内容与操作 | 13–15 逻辑像素 | 歌手、曲目、按钮、说明；优先可读 |
| 辅助标签与编号 | 11–12 逻辑像素 | `ALBUM / 专辑`、`TRACK RECORD`、时间、编号 |

字体使用清晰的无衬线系统字体：中文优先平台系统中文字体，拉丁文可使用 Helvetica Neue、Arial 或系统等价字体；时间和结构化编号可用等宽数字或等宽字体。保证中文、英文字形回退完整。标题字距可以略紧，英文大写标签可适当加字距，不能影响阅读。

早期视觉稿中个别英文装饰文字小于 11 像素；那是绘图示意，不应作为可读文字的交付标准。用户需要读取或操作的信息不应缩小成装饰。长标题允许合理换行或带省略号，完整内容应有可访问路径；不要为了放下长标题整体缩小页面。

### 文案规则

- 中文是主要交互语言；英文用于辅助分区，例如 `TRACK RECORD / 歌曲档案`、`ALBUM / 专辑`，不必每一行都重复双语。
- 标题用真实歌曲名、歌单名、艺术家名，不强行全大写、不翻译专有名词。
- 按钮用明确动作：`播放歌曲`、`加入歌单`、`播放全部`、`加入队列`、`收藏专辑`。不能把一组互不相同的操作都改为含糊的 `打开`。
- 略写编号、来源、质量和时长必须来自真实数据；未知时显示适当占位或省略，不编造连接状态、曲目总数、音质、推荐依据或错误原因。
- `RHINE LAB`、`AUDIO ARCHIVE`、`RL / 004` 等标识是示意性视觉素材。真实产品品牌、版权、音频来源和标识使用以项目已有资源及使用范围为准，不得让虚构状态冒充实际服务信息。

## 5. 空间、材质与图形

设计稿的尺寸用于建立比例，单位是**逻辑像素或平台等价单位**，不是设备物理像素。Qt 逻辑坐标、舞台坐标和系统缩放的换算必须遵循实际平台实现。

| 元素 | 基准范围 | 说明 |
| --- | --- | --- |
| 常用间距 | 4、8、12、16、24、32 | 相邻信息紧凑，职责不同的分区留出更多空间 |
| 桌面外边距 | 约 24–32 | 页面左右一致；由可用宽度与现有容器决定 |
| 面板内边距 | 约 18–25 | 保持标题、按钮、字段、分隔线的共同左边界 |
| 主结构线 | 2–3 | 仅用于主要档案面板顶部、表头等关键位置 |
| 普通分隔线 | 1 | 低对比度，通常贯穿同一内容列 |
| 主按钮高度 | 约 36–42 | 桌面可紧凑；触摸命中区域至少约 44 × 44 |
| 列表行高 | 约 44–56 | 根据文本、输入方式及既有列表密度调整 |
| 图标 | 约 14–18，线宽约 1.5–2 | 线性几何图标，图形细节与文字保持同一视觉重量 |

主要容器是大块不透明纸色平面；页面可以以略有区别的底色区分整体背景和档案面板。若使用投影，只保留非常轻微的层次；不依赖模糊阴影区分操作。二维唱片封面可以用一层薄边框和非常轻微的偏移实体层制造纸套感；这是构图建议，不是要求把已有的 3D 唱片变成图片或倾斜所有封面。

圆环应有具体作用：封面唱片的中心孔、播放状态、档案图形或分类标记。节点数量少、线宽轻、不能覆盖文本和命中区。轨道线属于辅助图形，不表示真实音频波形；没有真实信号数据时不要绘制看似精确的频谱。

## 6. 共用页面骨架

### 6.1 设计范围与页面层级

**默认只设计和展示用户指定的页面或组件。** 设计稿、交互预览和网页应聚焦该页面本身，不自动补齐整个应用外壳。

- 未经明确要求，不加入全局顶栏、导航栏、底部 Tab 栏、播放栏、侧边栏、其他页面的卡片或背景场景。
- 例如，设计歌曲评论页时，只展示评论页所需的标题、评论列表、排序、回复和输入等内容；不附带歌曲档案、专辑封面、播放控制或全局导航。
- 如果某项信息或操作是该页面完成自身任务所必需的，可以保留；不要仅为展示产品背景而加入无关模块。
- 用户明确要求展示页面与应用外壳的关系、完整界面或相邻模块时，再按要求提供相应上下文。

页面内部仍遵循统一的信息层级：标题和主要内容最醒目；主操作清晰；次要信息、英文标签和档案编号退居辅助层级。使用对齐、留白、细线及少量琥珀色标记组织内容。

评论排序、详情分类等**属于当前页面功能的控件**可以保留；不因避免全局导航而删除页面自身必要的交互。

### 6.2 基础组件

- **主按钮**：深墨绿黑实底、暖白图标与文字；必要时附简洁图标。悬停与按下可小幅改变底色，不能改变文本含义或造成布局跳动。
- **次按钮**：透明或浅色底、细线轮廓，颜色和主内容一致。次要动作不全部使用大面积灰色实底。
- **文字按钮**：文字与小图标同一基线，适合打开专辑、歌手或官方入口；必须有足够命中范围和可见焦点。
- **选项卡**：紧凑标签横排或根据空间换行；当前项深色文字与约 3 逻辑像素琥珀下划线配对，未选中项为次级文字。选择状态不得只靠黄色区别。
- **字段**：小号字段名在上，实际值在下；同类字段以两列或多列对齐，窄屏改为适合内容的排列。字段值比标签更重要。
- **列表行**：序号、标题、辅助信息、时间及动作形成稳定列；以细线分隔。当前曲目用浅色底与左侧琥珀色短条标识；另用图标或状态文字标识实际播放状态。
- **菜单与抽屉**：不透明浅色面板、深色顶部线或细边界，内容为真实操作。打开时应有清晰关闭方式、焦点顺序和 `Esc` 行为；不能被遮罩或页面其他控件穿透。
- **标签**：使用低对比浅底色或细线表示类型与质量；关键信息不能只作为无说明的装饰缩写。

### 6.3 状态与输入

正常、悬停、键盘焦点、按下、选中和禁用都需要明确视觉反馈；键盘焦点不能仅依赖悬停。对于播放中、暂停、加载、空结果、错误、无权限、离线和部分数据，使用文字或图标说明，避免用颜色独自表达。加载或失败时保留可行的返回与重试路径。

长列表要支持原有的滚动、分页或继续加载，不能为了匹配设计稿只保留可见的几首；缩略图和数据未加载时有稳定占位，不把封面或装饰当作交互命中区域。队列、喜欢、收藏、切换来源、播放及官方客户端交付继续遵守真实业务状态和权限。

## 7. 页面模式

### 7.1 歌曲详情：唱片对象 + 歌曲档案

桌面以两栏组织：左侧约 35–40% 为唱片或封面对象，右侧约 60–65% 为详情。两栏间留明显空隙；允许根据现有 3D 场景、窗口和内容调整，比例不是硬编码坐标。

```text
唱片 / 封面对象                  01  TRACK RECORD       真实歌曲 ID
实体资料标签                    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
                                来源 / 上下文
                                歌曲名
                                歌手
                                [播放歌曲] [喜欢] [加入歌单] [更多]
                                ───────────────────────────────
                                专辑             时长
                                音质             播放方式
                                歌曲百科   专辑信息   同专辑曲目
                                内容 / 来源 / 官方入口
```

左侧可以有唱片编号、细线和真实专辑名。右侧名称优先级最高，其次是歌手、播放动作，之后才是元数据与详情。`加入队列`、`下一首播放`、`歌手作品`等若收进更多菜单，仍须保留可发现性与原有能力。歌曲百科、专辑信息和同专辑曲目使用平行选项卡，切换后显示真实对应内容。

不要将正在浏览的歌曲误标为正在播放的歌曲：两者不同的时候，名称、播放操作、进度可操作性和当前播放提示必须反映各自状态。缺少音质、时长或百科资料时不要显示示意值。

### 7.2 发现音乐：精选区 + 目录

顶部是 `发现音乐` 和辅助英文标题；下方保留真实可用分类，例如推荐歌单、每日推荐、排行榜、新专辑、分类歌单、收藏歌手、历史。分类下划线与其他页面统一。

```text
发现音乐  Discover music
推荐歌单  每日推荐  排行榜  新专辑  分类歌单  …
────────────────────────────────────────────────────────
精选专辑 / 大型图文入口                  每日推荐 / 次级入口
────────────────────────────────────────────────────────
推荐歌单                                  查看更多 / 分页
封面 + 名称 + 真实来源或创作者信息（按内容数量排列）
```

示意稿的精选区约占横向空间的三分之二，次级推荐约占三分之一；下方以 2–4 列展示歌单或根据空间退化为列表。封面比例一致，长标题与来源分两层，入口可被整个卡片命中；缺图时使用统一的抽象档案占位，不伪造专辑封面或数据。分类的加载、空结果及分页仍需真实呈现。

### 7.3 专辑与歌单详情：实体资料 + 曲目目录

```text
ALBUM / 专辑                  专辑名称                         曲目总数
[真实封面]                    [播放全部]   加入队列
专辑名                        ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
艺术家                        #   曲目                  歌手     时长
发行时间 / 曲目数             01  …                      …        …
简介                          02  当前曲目               …        …
收藏 / 官方入口               …
```

封面侧栏在桌面通常约 170–215 逻辑像素，曲目表占其余空间，取决于容器尺寸。行内按真实需要保留歌曲名、歌手、专辑、时长、播放等字段；不能为与示意稿一致而丢失现有排序、收藏、播放来源或分页。所选行和实际播放行需要区分。歌单、艺人作品等相关面板可复用同一档案标题、信息侧栏和列表组件，但显示各自真实数据。

### 7.4 播放状态栏：档案终端

以暖白或浅灰绿的窄型不透明区域作为基底，按信息优先级排列：

1. 当前歌曲名称和艺术家，必要时附小型唱片标记。
2. 上一首、播放/暂停、下一首；播放状态的图标与无障碍名称同步变化。
3. 当前时间、可定位时的进度、总时长；已播放段使用琥珀色。
4. 真实可用的输出、音量、队列等次级操作。
5. 连接或播放提示只在确有对应状态时出现；可用更淡的底部细带承载。

状态栏的深色控制与页面主按钮一致；轨道装饰不能挤占歌曲名或操作空间。播放、暂停、缓冲、错误、无内容和不可定位分别需要文字或图标反馈。播放位置只能控制与当前播放身份一致的音频。

## 8. 自适应与平台边界

桌面优先使用并置的唱片对象与资料区；空间不足时先缩小间距、调整列宽和折叠次要文案，再将多列重排。发现页卡片由多列减少到两列或一列；专辑资料由侧栏变为顶部摘要，曲目行优先保留名称、可用操作和时长。完整信息仍应可访问，不把隐藏字段当成删除功能。

移动布局必须以实际窗口和平台约束为准，不简单套用网页断点。现有移动端是按窗口宽高关系选择布局，并有安全区、列表滚动、底部导航、迷你播放栏、三维唱片和输入坐标等明确约束；执行具体修改前阅读 [响应式 HUD 维护指南](RHINE-MOBILE-DESIGN.md)。不能把本文件中的网页示意比例直接作为 Qt 舞台坐标，或让弹层、内容命中区覆盖系统安全区与播放栏。

触控目标建议不小于约 44 × 44 逻辑单位，彼此不重叠；显示图标可更小。所有主要操作不依赖悬停。字号、输入光标、辅助功能标签及高对比度/减少动态效果应服从平台习惯与用户设置。

## 9. 动效原则

- **优先表达状态变化**：选项卡指示条、列表选择、抽屉开合、播放图标可以有短促、稳定的过渡；静态时不持续闪烁。
- **不破坏既有运动**：页面、唱片、相机、播放状态和场景间已有同步关系时，使用现有时间线和约束，不因视觉统一自行新增独立的整页转场。
- **不中断操作**：连续切换时从当前状态平滑接续；动画期间命中区域与可见位置一致。减少动态效果时使用立即切换或其他已有的简化方式。
- **无意义动效不常驻**：装饰性环线不需要无止境旋转，播放暂停后也不伪装成音频活动。

## 10. 新页面实施步骤

1. **确认设计边界**：只列入用户指定的页面或组件，以及完成该页面任务必需的内容和操作。默认不设计应用外壳、全局导航、播放栏或其他页面模块。
2. **列出真实内容与动作**：明确页面目标、数据来源、主次操作、空状态、加载、错误、权限及平台差异；区分浏览对象与正在播放对象。
3. **选择适合的页面结构**：依据当前页面的职责组织内容，不为套用模板而加入无关区域。
4. **套用统一视觉规范**：使用本文的语义颜色、字体层级、间距、分隔线、按钮和状态样式，并适配用户要求的明暗色。
5. **处理交互与边界**：检查长标题、缺图、无数据、加载失败、未登录、权限不足、长列表、窄窗口、触摸和键盘操作。
6. **检查设计范围**：交付前确认预览中没有未经要求的顶栏、全局 Tab 栏、播放栏、歌曲档案或其他页面模块。属于当前页面的必要控件除外。
7. **交付可查看的结果**：用户要求网页时，提供可打开的网页文件或可访问链接；使用示例数据或模拟交互时明确说明。

## 11. 交付验收清单

### 视觉一致性

- [ ] 画布、面板、文字、分隔线和强调色使用第 3 节语义，页面主要内容保持浅纸色 / 深文字体系。
- [ ] 标题、字段、操作、辅助说明的层级清楚；常用按钮、选项卡、列表行和状态栏符合第 6 节。
- [ ] 强调色用于少量选中、进度、提示或节点；没有大面积霓虹、无意义仪表图或过多灰色实底按钮。
- [ ] 封面与真实内容清晰，现有三维主体与重要场景不被示意图替换或遮挡。
- [ ] 中文可读、长文本有处理方式，英文只作为辅助；没有以示意编号或虚构状态冒充真实数据。

### 功能与可访问性

- [ ] 原有播放、加入队列、喜欢、收藏、导航、排序、分页、官方入口等适用操作仍可达，状态与真实数据一致。
- [ ] 播放中、暂停、加载、空、错误、未登录、无权限、不可定位等适用状态可区分，信息不只靠颜色。
- [ ] 键盘焦点可见；触屏目标充分且不重叠；文字、控件和状态具备平台所需的无障碍名称。
- [ ] 小窗口、长标题、封面缺失和长列表下无裁切、溢出、不可达或输入穿透；移动安全区按平台实际约束保留。
- [ ] 动效遵循现有场景和播放生命周期，并支持减少动态效果；切换歌曲不会把浏览状态误作播放状态。

### 验证方式

对每个修改页面至少检查正常、长标题、缺图、空/加载/错误及选中状态；在目标桌面尺寸和适用的窄窗口/移动布局中查看真实界面。涉及播放或导航时实际操作主路径与次级路径；涉及 3D 合成时同时观察封面、相机和面板关系。必要时保留固定输入的前后截图，确认信息层级、颜色和对齐；截图比对不能替代键盘、触控、真实音频或设备验证。

交付时说明哪些页面已调整、哪些只是设计稿，列出实际构建或测试结果，以及未在对应平台、设备、账号或 GPU 上验证的项目。
