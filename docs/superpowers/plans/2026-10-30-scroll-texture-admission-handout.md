# 快速滚动纹理优化 Handout

2026-10-30｜交接给 A01–A11 实施者｜基于 A08 继续，不重写渲染链路。

**目标：** 快速路过的条目不生成冷纹理；焦点稳定 100ms 后再准备标签／封面，正确缓存命中立即复用。

**已批准：** 100ms 冷资源准入＋过期需求取消＋现有有界 LRU。**不是失焦即销毁，不延迟网络请求。**

## B01：准入与唤醒

位置：`Qt/src/Engine.h`、`Qt/src/Engine.cpp`；纯判断可提取到 `Qt/src/render/MusicTextureAdmission.h`。

- [ ] 按**列表焦点 key** 和单调时钟计时，不按帧数；同 key 重复帧、封面晚到、revision 变化不重计时，采用最新内容。切走再回来重计时，正确缓存命中例外。
- [ ] GUI 线程只维护当前焦点的一次性定时器；回调核对 key／代号／可见状态。到期主动走 `requestSceneContent()` 通知链，并同步准入快照；不能靠持续出帧等到期，也不能跨线程操作 Renderer。
- [ ] 隐藏期间不创建 GPU 资源，恢复后重新核对。新增排障参数 `RHINE_TEXTURE_ADMISSION_MS`，默认 100，0 关闭延迟，非法值回默认；不加设置 UI。

## B02：把门槛放在昂贵工作之前

位置：`Qt/src/RhiScene.cpp` 的 `updateMusic()`、`render()` 及同步快照。

- [ ] 分开“更新当前身份／选择绑定”和“创建资源”；不能直接提前返回、让当前 key 留在上一首。标签和封面分别判断 revision／缓存，命中立即复用。
- [ ] 未准入时不执行标签绘制、缩放、mip、纹理创建或封面预处理；使用中性占位，不借用另一首的标签／封面。焦点、列表文字、HUD 和播放操作立即反馈。
- [ ] 检查遍历 `musicTextures` 的恢复分支，禁止为路过且从未准入的条目补做资源。已准入的可见归位卡片保留；设备恢复允许重建这些资源，单帧离屏参考保留 `forceSynchronousCover` 例外。

## B03：取消需求，不销毁热缓存

位置：同文件的 `coverWanted`、`discardCoverPrepFor()`、`drainCoverPrep()`、`uploadPendingCovers()`。

- [ ] 帧内**先更新焦点／有效需求，再消费结果和上传队列**。切走撤销无用需求；结果入队和实际上传前均判活，检查 revision／serial，防止迟到上传和孤儿纹理。
- [ ] 共享封面仍有消费者、已准入归位卡片仍需资源时不要误取消。逻辑取消不等于工作线程结束，**实际在途数仍须有界**，不能删除请求记录后反复释放并发名额。
- [ ] 保留现有 32 条／字节预算 LRU、活动保护、共享引用、安全退休及上传预算；不在失焦事件里直接释放，不加 GPU 空闲等待。维持 `Busy` 不退同步，取消／丢弃后允许重试。

## B04：测试与观测

新增 `Qt/tests/MusicTextureAdmissionChecks.cpp`，沿用 `Qt/tests/RenderChecks.cpp` 的 Core-only 风格；在 `CMakeLists.txt` 注册下列目标／测试名。

- [ ] 假时钟先测 0／99／100ms、同 key 不重计时、切焦重计时、旧回调失效、缓存部分命中、封面晚到、参数 0；不靠 sleep 测边界。
- [ ] 再测过期结果、共享 revision、取消后的实际并发上限、设备恢复准入；隔离计时器测试无持续帧仍通知、销毁后无回调。纯逻辑测试不能代替 GPU 生命周期验收。
- [ ] 扩展 `RHINE_TEXTURE_PROBE=1`：准入／取消数、标签生成次数与 CPU 耗时、实际在途峰值、过期丢弃、纹理创建／上传量、焦点稳定到换绑延迟。默认不刷高频日志；换绑时间不叫真实上屏时间。
