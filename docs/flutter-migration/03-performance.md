# 性能基线与测量方法（T52-D01）

- 状态：方法文档，不是测量报告。当前 Flutter 与 Qt 两侧的采集次数均为 0，本文件不含任何实测数字，也不宣称任何性能目标已达成。
- 计划依据：`docs/superpowers/plans/2026-11-09-qt-to-flutter-parity-plan.md:718-724`（T52）。该卡要求采集帧时间分布、首帧、内存、启动与 30 分钟稳定性，并在同一设备、同一场景下与 Qt 对比；所有指标在冻结前都是「拟议待冻结」。
- 采集器：`tool/perf/collect_frame_times.dart`（1518 行，revision `T52-S01`，见 :64）。它只消费 JSONL、只输出统计，不读设备、不联网、不 import Flutter、不内置阈值，也不产生通过/失败判定（:1-57、:211-212）。
- 协议：`tool/perf/README.md`。本文件说明「测什么、为什么这样测、当前为什么不可判定」；README 说明「输入怎样被读取、拒绝与汇总」。
- 本文件不定义产品性能目标，不替代 `docs/flutter-migration/02-adjudication.md` 的裁决，也不改变 T50/T51 的视觉未取证状态。

## 1. 判定词与证据纪律

本文件只使用以下词，不新增「基本流畅」「接近 60 帧」一类软判词。

| 词 | 含义 | 使用条件 |
| --- | --- | --- |
| `UNMEASURED` | 没有可复核的实测样本，或样本不足以支撑该指标 | 采集次数为 0、样本跨度为 0、或所需外部记录缺失 |
| `MEASURED` | 有原始 JSONL 与采集器报告，可重放、可核对 | 只能用于采集器实际输出的分布/跨度/峰值，不附带达标结论 |
| `NOT_EVALUATED` | 有样本但该窗口/该段不满足可评估条件 | 窗口未满、非空段少于 2 个等；不得把该状态改写成 0 或通过 |
| 拟议待冻结 | 候选指标或候选比较方式，尚未被验收流程冻结 | 不得当作承诺、门槛或发布条件 |
| 不判定 | 本文件与采集器都不给出通过/失败 | 裁决留给冻结后的验收流程 |

证据纪律（与 `02-adjudication.md:10-26` 一致）：

- 没跑过就不得填数字；没采集就不得用源码常量、QML 预览、设计稿或桌面离屏图替代真机样本。
- 采集器报告只回显输入（`deviceData: echoed from the input; nothing is synthesised`，collector :600-638）。任何手改过的 JSONL 都不再是原始证据。
- 采集器没有阈值（`thresholds: 'none'`）也没有判定（`verdicts: 'none'`）。因此「报告已生成」不等于「性能已通过」。
- 当前 `02-adjudication.md:14` 记 E0 采集数 = 0；本文件的所有结果位因此只能是 `UNMEASURED`。

## 2. 指标族

「当前值」列全部是状态，不是数字。协议常量（例如 30 分钟窗口、9 个必填字段）不是性能结果。

| # | 指标 | 来源/派生 | 单位 | 定义 | 当前值 |
| --- | --- | --- | --- | --- | --- |
| M1 | 帧时间分布 | `frameTimeMs` → p50/p95/p99/max/mean | ms | 单帧从开始到完成的耗时，按 run 汇总；nearest-rank 分位，不插值（collector :278-286） | `UNMEASURED`（0 run） |
| M2 | 帧数与采样跨度 | `timestampMs`、`frameIndex` | 帧、ms | 一个 run 内首末样本时间差；只证明采样覆盖，不证明帧率 | `UNMEASURED`（0 run） |
| M3 | 首帧标记偏移 | `firstFrame` 标记帧的 `offsetFromRunStartMs` | ms | 标记帧时间戳减该 run 第一个样本时间戳；不是进程启动延迟（collector :742-762） | `UNMEASURED`（无标记样本） |
| M4 | 内存峰值 | `memoryMb` 最大值及位置 | MiB | 生产者上报的每帧内存值之最大值；采样口径由生产者决定（collector :790-794） | `UNMEASURED`（0 run） |
| M5 | 启动耗时（自报） | run 内最早样本的 `startupMs` | ms | 原样回显该值；basis 明确写「earliest sample」，不是进程冷启动测量（collector :795-801） | `UNMEASURED`（0 run） |
| M6 | 30 分钟稳定状态 | `observedSpanMs >= windowMs` | 状态 | 仅按时间跨度判定样本是否覆盖窗口；不推断崩溃/ANR/OOM（collector :839-945） | `UNMEASURED`（无 run） |
| M7 | 窗口漂移 | 首末非空段的 p50/p95/内存峰值差 | ms、MiB | 只给带符号 `fromValue/toValue/delta/ratio/direction`，无阈值、无判定（collector :1047-1108） | `UNMEASURED`（无窗口） |
| M8 | 拒绝与冲突 | `rejectedLines`、`conflictedRunFrames` | 行、帧 | 数据质量计数；冲突 run 全量拒绝，不做部分保留（collector :547-556、:636-646） | `UNMEASURED`（无输入） |

补充约束：

- 采集器不计算 fps，也不定义 jank。M1 是帧时间，不是帧率；不得用 `1000 / p50` 反推一个「fps」再当验收值。
- 采集器 schema 不含刷新率。设备刷新率、分辨率、density 必须在外围记录（见 §4.4）；刷新率缺失时，「流畅」类结论一律 `UNMEASURED`。
- 采集器 schema 不含热状态、充电状态、后台负载、屏幕亮度。这些必须在外围记录；缺失时跨 run 可比性 `UNMEASURED`。
- 内存值来自生产者上报，采样间隔与是否包含 native/graphics 内存均未在本原子中定义。因此 M4 在生产者口径冻结前只能单侧观测，不能做跨实现结论。

## 3. 场景定义（必须先冻结）

性能比较的单位不是「一次启动」，而是 `(deviceId, sceneId, runId)` 三元组。同一 runId 只允许一个 `(deviceId, sceneId)` 组合；出现第二种组合时，该 runId 的所有帧都被拒绝（collector :490-556）。

### 3.1 sceneId 必须固定以下维度

| 维度 | 必填内容 | 不固定时的后果 |
| --- | --- | --- |
| 页面/动作 | 例如首页静止、资料库滚动、搜索输入、歌曲详情、播放中、设置展开 | 不同动作的帧时间不可合并 |
| 状态 | idle / active / transition，三者只选一个 | 静止低帧率会被误读为退化（计划 :722 明确静止低 fps 正常） |
| 方向与几何 | 横屏 2880×1800、dpr 1.96875（landscape.md:8-9）；竖屏另立场景 | 几何不同不可比 |
| 主题 | 浅色/深色只选一个 | 渲染路径可能不同 |
| 账号态 | 未登录/已登录只选一个；账号域当前 PAUSED_BY_USER | 登录态无真机画面，不能补位 |
| 数据规模 | 曲目数、专辑数、当前列表位置（例如第 17/933） | 长列表位置影响滚动负载 |
| 播放态 | 空队列/播放中/暂停/seek 只选一个 | 后台播放会改变主线程负载 |
| 网络态 | 离线/在线只选一个；在线需固定是否触发封面与歌词请求 | 网络抖动会污染帧时间 |
| 采样时长 | 分布场景与 30 分钟稳定场景分开命名 | 短场景不能冒充稳定场景 |

### 3.2 两侧对照的同一性

- 同一设备：serial `526f6b6d`（OPD2511，Android 16 / API 36 / arm64-v8a，device-2026-11-09.md:7）。
- 同一几何：物理 2880×1800、density 315（device-2026-11-09.md:16-29）。
- Qt 侧构建：APK `output/RhineMusicDatabase-01ee85b96fee-android-arm64-v8a-signed.apk`，SHA256 `bd58d95a5edee4c66a9704a108fb335163dc4274239b5f32b2a0c4cb221b5a1e`（device-2026-11-09.md:8-9；00-baseline.md:331）。
- Flutter 侧构建：必须记录完整 commit SHA 与 APK SHA256；当前没有可引用的 Flutter 性能包。
- 同一状态脚本与同一操作序列：两侧使用同一份脚本文本；任何一侧改脚本，必须新开 sceneId，不得复用旧 runId。
- 同一采集顺序：同一场景先 Qt 后 Flutter 或反之均可，但必须在元数据中写明；不得交错合并两个实现的样本。

### 3.3 不能作为性能场景的输入

- `Assets/previews/*.png` 的 9 张 3024×1898 图不是真机帧（landscape.md:20），不能作为性能场景的视觉基准。
- 已丢失的 12 张基线 PNG 只剩索引（device-2026-11-09.md:130-156），不能作为性能采集的对照帧。
- QML 预览、桌面离屏渲染、模拟器、单元测试里的假时钟都不是设备样本。

## 4. 采集方法

### 4.1 前置条件

1. 设备已安装待测包；包 SHA256 已记录；设备型号、系统版本、density、物理分辨率、刷新率已记录。
2. 场景脚本已冻结，包含每一步的输入、等待条件、开始/结束标记；脚本版本写入元数据。
3. 采集器 revision 固定为 `T52-S01`；如采集器改动，必须新 revision 并重跑全部场景。
4. 设备处于已知热状态（冷机/预热完成二选一）并记录；充电状态、亮度、音量、勿扰、后台应用列表已记录。
5. 关闭无关后台同步；如需保留账号态，先记录账号态，但不得在证据中写入凭据内容。

### 4.2 数据生产

采集器只接受 JSONL，不负责从设备取数。仓库当前没有帧时间生产者或 harness：`tool/perf/` 只有 `collect_frame_times.dart`，没有采集脚本、没有 `.jsonl` 样本。生产者属于后续采集任务，本原子不实现、不执行。

生产者必须为每一帧写出 9 个必填字段（collector :87-98）：

| 字段 | 类型 | 约束 | 语义 |
| --- | --- | --- | --- |
| `deviceId` | string | trim 后非空 | 设备稳定标识；不得用随机数 |
| `sceneId` | string | trim 后非空 | 冻结后的场景标识 |
| `runId` | string | trim 后非空；一个 run 只对应一个 device+scene | 单次采集标识 |
| `frameIndex` | int | >= 0；不接受 `1.0` | run 内帧序号 |
| `frameTimeMs` | num | 有限且 >= 0 | 帧耗时（ms） |
| `timestampMs` | int | >= 0；不接受 `1.0` | 帧时间戳（epoch ms） |
| `firstFrame` | bool | true/false | 是否启动后首帧标记 |
| `memoryMb` | num | 有限且 >= 0 | 该帧采样内存（MiB） |
| `startupMs` | num | 有限且 >= 0 | 生产者自报启动耗时（ms） |

生产者必须在文档中写明：帧时间的起止点（build/raster？）、内存采样间隔与包含范围、startupMs 的起点与终点、首帧标记的插入点。上述任一项未写明，对应指标只能记 `UNMEASURED`。

### 4.3 采样时长与窗口

- 分布场景：建议每个场景至少覆盖一个完整操作循环，具体时长由场景脚本冻结；本文件不预设秒数。
- 稳定场景：采集器默认窗口 30 分钟（`_defaultWindowMinutes = 30.0`，collector :68），窗口切成 6 段（:71）。这只是协议常量，不是性能门槛。
- 30 分钟稳定场景必须单独 run，不得把多个短 run 拼接后声称覆盖 30 分钟；采集器只看单 run 内首末时间戳（:839-945）。
- 稳定场景还需设备侧日志证明无崩溃/ANR/OOM。采集器不读日志，缺日志时稳定门只能 `UNMEASURED`，不能因为 `stability.status == MEASURED` 就宣称稳定通过。

### 4.4 外围记录（采集器 schema 之外）

以下内容必须与 JSONL 一起归档，否则报告不完整：

- 设备：serial、型号、Android 版本、API、ABI、density、物理分辨率、刷新率、当前亮度。
- 构建：commit SHA、APK SHA256、applicationId、versionCode/versionName、签名证书 SHA256（只记证书，不记私钥）。
- 场景：sceneId、脚本版本、操作序列、起始/结束界面截图（截图是状态证明，不是性能样本）。
- 环境：热状态、充电、音量、勿扰、后台应用、网络、账号态。
- 日志：崩溃/ANR/OOM 的 logcat 片段或系统事件；没有则明确写「未采集」。

### 4.5 归档与可重放

- 原始 JSONL 只读保存，不手工修补；被拒行保留在原文件，不删除。
- 报告 JSON 与输入 JSONL 一起保存；报告中的 `input.path`、`input.bytes`、`input.fingerprintFnv1a32` 用于绑定输入（collector :580-599）。
- 同一输入、同一采集器 revision 的输出应是确定的：采集器不写墙钟时间、不写随机数、不联网。可重放性以「同输入同字节」为验收方式。
- FNV-1a 32 位指纹只用于输入绑定，不是安全哈希；不得用它替代 SHA256 做证据完整性声明。

### 4.6 反污染规则

- 不得手工编辑 JSONL 让某行通过校验；不得删除被拒行；不得只挑好看的 run 上报。
- 不得把冲突 run 的帧拆到多个 runId 规避全量拒绝（collector :547-556）。
- 不得用不同 deviceId/sceneId 的样本拼成一个 run；不得用不同构建的样本共用一个 sceneId。
- 不得把「采集器退出码 0」当成「性能通过」；退出码 0 只表示报告已写出（collector :182-213）。

## 5. 分析协议

### 5.1 分布

- 分位：nearest-rank，`ceil(q*n)-1`，越界夹取，不插值（collector :238-250、:278-286、contract :609）。
- 输出：count、min、p50、p95、p99、max、mean；派生值保留 6 位小数，样本原值不改（collector :611-616）。
- 空序列返回 null，不返回 0（collector :252-262）。null 必须在报告中读作「无样本」，不得读作「0 ms」。

### 5.2 30 分钟与窗口

- `stability.status` 只有 `MEASURED`（首末跨度 >= 窗口）与 `UNMEASURED`（不足窗口）两种；不足时给出 `shortfallMs`（collector :919-936）。
- 窗口未满：该窗口 drift 为 `NOT_EVALUATED`，reason `window_not_fully_spanned`；非空段少于 2：`NOT_EVALUATED`，reason `fewer_than_two_non_empty_segments`（collector :1047-1108）。
- 跨窗口 rollup 只汇总 EVALUATED 窗口，三指标固定出现；没有判定（collector :1111-1199）。
- 采集器明确 `sampleCountUsedForDuration: false`（:936）：不能用「样本很多」替代「时间跨度足够」。

### 5.3 首帧、启动、内存

- 首帧偏移是「标记帧相对该 run 首样本」的偏移，不是应用启动到首帧的延迟；若生产者从启动后才开始写样本，该偏移会偏小（collector :742-762）。
- startupMs 是生产者自报值，汇总取最早样本；采集器不验证其起止点（collector :795-801）。在生产者口径未冻结前，只能称「自报启动耗时」，不能称「冷启动耗时」。
- 内存峰值是上报值的最大值；采集器不采样、不校验间隔（collector :790-794）。跨实现比较前必须统一采样口径，否则记 `UNMEASURED`。

### 5.4 与 Qt 的对比

- 对比必须是同设备、同几何、同场景、同脚本、同账号态、同网络态、同热状态的两份 run。
- 报告并列呈现两侧分布与峰值，不计算「提升百分比」作为结论；如需比值，只在分母非 0 且商有限时给出，并标注「描述性比值，不是门槛」。
- Qt 侧目前没有性能 run：12 张基线图是视觉索引，不是性能样本（device-2026-11-09.md:104-117、:130-156）；`02-adjudication.md:131-139` 把 Qt 同设备同场景基线列为未评估项。
- 若 Qt 侧无法运行，只能记 `UNMEASURED`，不能拿旧截图、QML 预览或桌面版替代。

## 8. 失败与不可判定矩阵

| 条件 | 采集器行为 | 报告应怎样读 | 不能宣称 |
| --- | --- | --- | --- |
| 输入文件缺失/不可读/非 UTF-8/无记录 | 退出码 2，不写报告（collector :182-213） | 采集未发生 | 任何性能结论 |
| 单行 JSON 语法错/非对象/缺字段/类型错/空标识/负数/非有限 | 整行拒绝，计入 `rejectedLines`，其他行继续（:400-440） | 报告有拒绝计数；不得忽略 | 被拒行代表的场景 |
| 同 runId 出现第二种 device+scene | 该 runId 全部帧拒绝，`rejectedRuns` 增加（:547-556） | 该 run 无样本 | 该 run 的任何指标 |
